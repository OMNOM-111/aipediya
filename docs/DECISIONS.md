## D-2026-09-26-shared-server-ssh

- Статус: подтверждено владельцем (2026-09-26)
- Решение: AIpediya и StratForge размещены на одной серверной машине.
  Исполнителям AIpediya разрешено использовать существующий настроенный
  SSH-доступ к этой общей машине для работ исключительно в контуре AIpediya.
  Запрет «не трогать StratForge» относится к файлам, данным, процессам,
  сервисам, туннелям, конфигурации и секретам StratForge, а не к самому факту
  SSH-подключения к общей машине. Не читать, не копировать, не изменять и не
  раскрывать приватные SSH-ключи; разрешено использовать уже настроенную SSH
  identity для подключения к общей машине, если действия строго ограничены
  контуром AIpediya. После подключения — сначала read-only проверка (hostname,
  пользователь, `/srv/aipedia`, программа `aipedia`, текущий release, preflight).
  Подробно — `AGENTS.md`, раздел «Общая серверная машина и SSH».
- Заменяет: неоднозначные записи «StratForge-ключи не используются» и
  трактовку SSH-канала как запрета на доступ к серверу.
- Источник: уточнение владельца 2026-09-26.

## D-2026-09-26-number-order

- Статус: подтверждено владельцем (2026-09-26, замечание приёмки)
- Решение: сортировка по номеру — по числовому `public_number`, строго вверх
  (1, 2, 3…) или вниз; хронологические режимы `release_asc`/`release_desc`
  (по умолчанию — новые сверху) упорядочены по ключу (дата выпуска, номер),
  то есть совпадают с порядком master (дата, имя, Record ID) и при обратном
  направлении разворачивают и записи с одинаковой датой; номера при этом
  строго убывают/возрастают. Точные и приблизительные даты не группируются:
  приблизительная дата остаётся приблизительной и участвует своим началом
  периода. Записи без номера — в конце обоих направлений. Порядок задаётся до
  пагинации; порции подгрузки продолжают его; ответ устаревшего запроса
  подгрузки не добавляет строки. Фильтры номера не пересчитывают.
- Причина исправленного дефекта (200 → 197 → 198): ключ хронологической
  сортировки был одной датой, а `sorted(reverse=True)` сохраняет исходный
  (возрастающий по номеру) порядок равных элементов.
- Заменяет: в `D-2026-09-24-permanent-catalog-numbers` абзац «Сортировка по
  выпуску: точная дата → приблизительная дата → неизвестные в конце».
- Реализация: `catalog/comparison.py` (`release_order_key`), `static/site.js`,
  тесты `catalog/tests/test_number_order.py`.

## D-2026-09-25-locale-paths

- Статус: предложено (инженерное решение делегировано исполнителю мандатом
  GSD-1.0 и реализовано в Local; владелец отдельно этот вариант **не**
  согласовывал; разрешения на Production нет — только по `docs/RELEASE.md`
  после утверждения выпуска GSD-1.0)
- Дата: 2026-09-25
- Сравнение на проекте. A — индексируемый `?lang=` (как на Production
  `ed103a3`): Google в руководстве по многоязычным сайтам помечает URL-параметры
  как «Not recommended»; язык «голых» адресов у нас зависел от cookie /
  Accept-Language / страны, т.е. один URL отдавал разные языки (нужен
  `Vary: Cookie`, риск смешения кэша); подборки и датасеты пришлось бы тоже
  держать на параметрах. B — пути локалей: один язык на адрес, простой кэш,
  hreflang/sitemap без параметров, подборки и страницы данных без особых
  правил; цена — одноразовый 301 для всех старых ссылок и сопровождение
  таблицы редиректов. Известные проиндексированные адреса — только то, что
  видно без консолей: sitemap Production (443 `?lang=en` + 22 alternates);
  входящие ссылки неизвестны (нет Search Console) — это не «их нет».
  Выигрыш в ранжировании не утверждается.
- Решение: B. English — на корне без префикса и служит `x-default`
  (страница 200, self-canonical); остальные 21 локаль — `/<код-в-нижнем-регистре>/`
  (`zh-hans`, `zh-hant`, `pt-br`). Язык определяется только путём; cookie,
  Accept-Language, страна и User-Agent его не меняют; языковых/IP-редиректов
  нет (Google: избегать автоматического перенаправления между языковыми
  версиями). Ручной выбор запоминается только в браузере; сервер не выставляет
  языковую cookie и ответы не варьируются по ней. Старые `?lang=`/`?kind=`,
  `/en/…`, не канонические написания кода — один 301 без цепочек; неизвестные и
  скрытые записи — 404. Единый построитель: `catalog/locale_urls.py`.
  Карта редиректов — `docs/SEARCH_DISCOVERY.md` §1. Ключи переводов не менялись.

## D-2026-09-25-facets-pagination

- Статус: предложено (реализовано в Local)
- Дата: 2026-09-25
- Решение: индексируются чистые каталоги и их `?page=N` (в диапазоне,
  self-canonical); `page=1` → 301, вне диапазона/мусор → 404. Любые фильтры,
  поиск, сортировка — `noindex,follow` без canonical на корень; на карточках
  такие параметры канонизируются к чистой карточке. `robots.txt` Production
  запрещает только перечисленные фасетные параметры и `partial`, не трогая
  `page` и пути локалей. Фрагменты `partial` — `X-Robots-Tag: noindex`.

## D-2026-09-25-discovery-outbox

- Статус: предложено (реализовано в Local; отправки на Production не включены)
- Дата: 2026-09-25
- Решение: IndexNow через журнал `DiscoveryEvent` (миграция 0018) и команду

## D-2026-09-24-model-verification-registry

- Статус: заменено новым решением (`D-2026-09-24-catalog-master`)
- Дата: 2026-09-24
- Решение: `AI_CONTEXT/AIpediya_Model_Verification_Master.xlsx` —
  обязательный verification-layer перед публикацией модели в AIpediya. В нём
  все скрытые модели Local (на 2026-09-24 — 459, все `TO_VERIFY`) и все
  будущие кандидаты. Статусы `TO_VERIFY / VERIFIED / READY_FOR_SITE /
  PUBLISHED / REJECTED`; публикация только после `VERIFIED` и только строк
  `READY_FOR_SITE`. Exact date — только подтверждённая; иначе надёжная `≈`
  дата первого публичного существования; `Exists` ≠ `YES` (future/rumor/
  unconfirmed) — запись только в таблице. Опубликованная модель получает
  постоянный `public_number` (см. `D-2026-09-24-permanent-catalog-numbers`).
  Колонка `Missing Data` показывает недостающее до `VERIFIED`.
- Реализация: `catalog/verification_master.py`, команда
  `manage.py verification_master sync|check` (только чтение базы; ручные
  колонки при sync не перезаписываются). Ссылки и даты из исследовательского
  импорта **не** переносятся в Official Source / даты: они лежат в служебных
  колонках `Import Sources (unverified)` / `Research Date Hint` (в 29 скрытых
  записях импортный источник — заглушка Smithsonian Mark I Perceptron).
- Отклонено: публиковать скрытые модели без строки в реестре; заполнять
  Official Source/даты непроверенными значениями импорта.
