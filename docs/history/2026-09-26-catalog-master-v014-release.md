## 1. Порядок номеров

Воспроизведено на рабочем Local: в режиме по умолчанию (`release_desc`) 58
нарушений, например 305 → 306 → 307. Причина — не приблизительные даты: ключ
хронологической сортировки в `catalog/comparison.py` был одной датой, и
`sorted(reverse=True)` сохранял исходный порядок равных элементов (по возрастанию
номера). Исправление: общий ключ `release_order_key` = (дата, номер, pk) для Models и
Tools — совпадает с порядком master (дата, имя, Record ID), разворачивает и записи
одной даты; приблизительные даты остаются приблизительными, записи без номера — в
конце обоих направлений. Сортировка по номеру уже шла по числовому
`public_number` в БД. Клиент: ответ устаревшего запроса подгрузки не добавляет
строки. Тесты `catalog/tests/test_number_order.py` (одинаковые точные даты,
приблизительные, оба направления, фильтр, границы порций, недатированные, смена
сортировки) — со старым ключом дают 8 провалов, с исправлением 7/7 OK. Рабочий
Local по отрисованной таблице: модели 310 → 1 и 1 → 310 строго, инструменты
112 → 1 и затем 27 без номера; подгрузка 4 порций 310 → 1 без разрывов.
