# Catalog master: как вести базу и готовить обновление сайта

Действующая книга одна: `AI_CONTEXT/AIpediya_Model_Verification_Master.xlsx`
(схема `aipediya-catalog-master/4`, версия v014; v013 — резервная копия). Версии v001–v012 и черновик
v013 — неактивные резервные копии в `backups/catalog-master-finalize-20260925/`
(контрольные суммы — `SHA256SUMS.txt`, `APPLY_MANIFEST_*.txt`). Правила полей —
лист `Rules` книги и раздел master в `AGENTS.md`.

## Владельцу: четыре операции в Excel

Перед работой закрыть книгу в других программах. После сохранения сказать
агенту: «в master есть изменения, подготовь обновление Local». Сохранение книги
сайт не меняет.

1. **Добавить находку.** Новая строка внизу листа `Models` (модель) или `Tools`
   (приложение, сервис, платформа). Достаточно `Name`, `Developer` и
   `Official Source` (ссылка). Не заполнять `Record ID`, `Status`,
   `Public Number`, `Missing Data`, `Missing Count` — их вычислит агент. Такая
   строка — черновик: сохраняется, но на сайт не попадает, пока агент не
   проверит её и не поставит `Status = PUBLISHED`.
2. **Исправить запись.** Изменить значение ячейки в существующей строке.
   `Record ID` никогда не менять.
3. **Добавить alias.** В колонку `Aliases` той же строки через ` | `
   (пробел, вертикальная черта, пробел), например `GPT 4 | gpt-4-0314`.
   Alias — только другое имя той же модели. Другой размер, Base/Instruct, режим
   с другими ценами — отдельная строка.
4. **Явно очистить поле.** Вписать `<CLEAR>`. Пустая ячейка означает «нет
   новых сведений» и ранее подтверждённое значение не стирает.

## Подготовлено ≠ опубликовано

* `Status = PUBLISHED` — запись **разрешена** в пакет публикации.
* `On Local` / `On Production` — **фактическое** наблюдение на дату из Meta
  (`Last Import`, `Production Checked`).
* Новые карточки 2026-09-26 имеют `On Local = YES`, `On Production = NO`: на
  публичном сайте их нет до отдельного выпуска.

## Номера (правило владельца 2026-09-26)

Record ID и адрес карточки постоянные. `Public Number` — хронологическая
позиция публичной записи: отдельно Models и Tools, по подтверждённой точной,
иначе приблизительной дате (начало периода); при равной дате — по имени, затем
Record ID. Непубличный резерв и записи без подтверждённой даты номера не
получают и сортируются в конце. Историческая находка встаёт на своё место,
сдвиги пишутся в `Changelog` книги и в ревизии Local. Сортировки и фильтры сайта
номера не пересчитывают.

## Агенту: порядок пополнения

1. Прочитать `AGENTS.md`, `docs/EXECUTION_STATE.md`, этот файл.
2. Найти изменения владельца: сравнить книгу с последней резервной копией
   (XLSX не коммитится); строки без `Record ID` — черновики.
3. Поиск во всей книге (Name, Aliases, Developer, model ID, Official Source),
   включая ARCHIVE. `check` предупреждает о совпадении имени с чужой записью
   или alias. Повторная находка не отменяет ARCHIVE.
4. Проверить только нужное для решения (идентичность, разработчик, назначение,
   дата, тип выпуска) по первичным источникам. Неизвестное — пусто.
5. Решение: `Publication Decision`, `Decision Code`, `Reason`, `Decision Date`,
   `Decision Sources`; для той же сущности — `Canonical / Parent Record ID` +
   `Relation Type`; в пакет — `Status = PUBLISHED`.
6. `.\.venv\Scripts\python.exe manage.py catalog_master refresh` — Record ID
   черновикам, Missing Data, счётчики, номера, Meta; всё в `Changelog`.
7. `… catalog_master check` → `check: OK`.
8. На копии Local: `$env:AIPEDIA_DB='<копия>'`, `… migrate`,
   `… catalog_master sync-local --plan-out plan.json`, затем `--apply`
   (защита `--max-changes`, по умолчанию 200), `… catalog_master import --path <копия книги>`,
   повторный `sync-local` должен дать 0 записей в базу.
9. Diff — владельцу. После приёмки: резервная копия рабочей базы, `sync-local
   --apply` на рабочем Local, `import`, `check`, переводы
   (`translate_catalog --dry-run`, затем запуск только в пределах бесплатного
   лимита), Local QA.
10. Production — только по отдельной команде владельца по `docs/RELEASE.md`:
    план выпуска (`release-plan` / `apply-plan`) переносит состав, поля и
    перенумерацию с проверкой ожидаемых старых значений (раздел «Выпуск»).

## Контракт sync-local (что переносится на самом деле)

| Данные | Переносится | Условие |
|---|---|---|
| Публикация (`published`) | да | по `Status` |
| Aliases (поиск) | да | непустая ячейка `Aliases` |
| 301 со скрытого дубля на канон | да | ARCHIVE + DUPLICATE_OF / ALIAS_OF / FORMAT_OF / MODE_OF, канон PUBLISHED; канон в другом листе — `Models:<Record ID>` / `Tools:<Record ID>` (например, модель, ошибочно заведённая как инструмент) |
| Владелец существующей строки Offers / Access | да: строка переносится к записи, указанной в master (Record Type + Record ID), с ревизией у обеих записей | новая запись-владелец PUBLISHED |
| Номер (`public_number`) | да | план `Public Number`; прежние номера — в ревизиях |
| Даты (точная / ≈ с точностью) | да | только PUBLISHED; пара дат — одним значением |
| Стадия, статус жизненного цикла, категория, задачи, модальности, контекст, лицензия, открытые веса | да | только PUBLISHED |
| Description EN / RU; у моделей также Suitable EN/RU и Limitations EN/RU | да | только PUBLISHED; остальные 20 языков — через `translate_catalog` |
| Инструменты: purposes, local execution, official URL | да | только PUBLISHED |
| Ссылка «Источник» записи | да: переключение на Source URL из master (существующий источник сохраняет свой заголовок) | только PUBLISHED |
| Платформы инструмента | да: недостающие добавляются, лишние **не** удаляются (удаление → предупреждение) | только PUBLISHED |
| Сервис доступа (вид, URL, место вычислений, имя) | да, если сервис принадлежит только этой строке доступа | запись PUBLISHED; общий сервис → предупреждение |
| Цены — существующие строки Offers (Key `offer-N`) | да: сумма, единица, условия EN/RU, active, primary, дата проверки, ссылка на источник; Billing Unit — только при Unit=other | запись PUBLISHED |
| Оценки — существующие строки (Key `evaluation-N`) | только флаг `Public` | любая запись |
| Новые записи | создаются: модель/инструмент, семья, разработчик, источник, страны, платформы | только PUBLISHED; черновики и отложенные — нет |
| Названия, разработчики, семьи, заголовок/издатель общего источника, Suitable/Limitations, Ecosystem, страны существующих записей | **нет** → предупреждение `unsupported` | |
| Новые строки Offers / Access / Evaluations / Origins, изменения общего (разделяемого) сервиса доступа | **нет** → предупреждение `unsupported` | |
| Billing Unit при стандартной единице (input, minute…) | **нет** → предупреждение (справочная пометка; на сайте заменила бы локализованную подпись и исключила цену из сравнения) | |
| Даты проверки строк Access, Conditions Extra (JSON), внутренние Facts (scoped_verification и т. п.) | нет (служебные) | |
| Редакционные поля (Decision Code, Reason, Notes…) | нет (только в книге) | |
| Поля непубличных записей | нет (не публичны) — счётчик `note` в выводе | |

Команда в конце печатает `WARNING: N differences … NOT transferred (X affect
public data, Y are service/representation differences)`; полный список —
`--plan-out` (kind `unsupported`, поле `category`). На 2026-09-26 — 124:
30 публичных в очереди (11 ссылок на общих сервисах, 16 новых строк доступа,
3 новые цены — нужен новый сервис и проверка единиц) и 94 служебных
(ссылки-доказательства доступа, справочные единицы цен, заголовки общих
источников) — `artifacts/catalog-master-v013-final/unsupported_classified.csv`.

## Выпуск на Production (по отдельной команде владельца)

* `catalog_master release-plan --plan-out <plan.json>` — на копии исходного
  снимка Local, сверенного с публичными данными Production (это не копия
  серверной БД): план с ожидаемыми старыми значениями по Record ID, итоговыми
  номерами и составом публикации. Серверный preflight `apply-plan` обязателен;
  при несовпадении — остановка, без принудительного применения и без
  перестроения плана на сервере.
* `catalog_master apply-plan --plan-out <plan.json> [--apply]` — на цели:
  pending → применить одной транзакцией с ревизиями; applied → ничего не писать;
  расхождение или частичное применение → отказ без записи.
* `deploy_code_release.py … --catalog-plan … --translations … --publication-state …`
  выполняет это внутри своей резервной копии и отката (`docs/RELEASE.md`).

## Отложено (не блокирует работу)

* 441 непубличная модель исследовательского запаса: 363 с предложением PUBLIC
  и пометкой `[DEFERRED 2026-09-26]`, 78 NEEDS_REVIEW с вопросом в `Reason`.
  Проверять по приоритету владельца, не сплошь.
* Kimi K3 (max) и Grok Voice API — объединение не применено, вопрос в `Reason`.
* 11 оценок Artificial Analysis — `Public = NO` до документального основания.
* 30 публичных неподдерживаемых расхождений (очередь, см. выше); 415
  непубличных записей резерва отличаются от Local — не синхронизируются.
