# AIpedia — порядок для исполнителей

Это **единственный** канонический текст правил для агентов и редакторов
(Cursor, Codex и любых следующих). Файлы правил редакторов только
подключают этот документ и **не** повторяют его содержимое.

## Главное правило

1. Любые доработки сначала выполняются и проверяются в **Local**.
2. **Production** изменяется только после отдельного явного разрешения
   владельца на **конкретный** выпуск по `docs/RELEASE.md`.
3. `git commit`, `git push` и кнопка **Production** в шапке Local
   **не** являются разрешением на публикацию.
4. Локальную SQLite **не** копировать поверх серверной базы.
5. Номера каталога, данные карточек (цены, оценки, ссылки) и git-историю
   сохранять.
6. **StratForge**, туннель Production и секреты не затрагивать — в смысле
   раздела «Общая серверная машина и SSH» ниже.

## Общая серверная машина и SSH (правило владельца 2026-09-26)

AIpediya и StratForge размещены на одной серверной машине. Исполнителям
AIpediya разрешено использовать существующий настроенный SSH-доступ к этой
общей машине для работ исключительно в контуре AIpediya. Запрет «не трогать
StratForge» относится к файлам, данным, процессам, сервисам, туннелям,
конфигурации и секретам StratForge, а не к самому факту SSH-подключения к
общей машине. SSH — транспорт доступа; StratForge — отдельное приложение.

- Разрешено: подключаться по существующему SSH; работать только с AIpediya
  (`/srv/aipedia`, серверная БД AIpediya по `docs/RELEASE.md`, backup,
  миграции, перезапуск только программы `aipedia`, проверка `aipediya.com`,
  `/healthz`, логов AIpediya); выполнять утверждённый владельцем выпуск.
- Запрещено: изменять, читать без необходимости или выполнять команды в путях
  StratForge; останавливать/перезапускать его процессы; менять его БД,
  Supervisor/systemd, Cloudflare tunnel, DNS, секреты.
- Ключи: не читать, не копировать, не изменять и не раскрывать приватные
  SSH-ключи; не генерировать и не заменять ключи без отдельной причины.
  Разрешено использовать уже настроенную SSH identity для подключения к общей
  машине, если действия строго ограничены контуром AIpediya.
- После подключения сначала только read-only: hostname, пользователь, наличие
  `/srv/aipedia`, состояние программы `aipedia`, текущий release, серверный
  preflight выпуска. Каталоги StratForge не исследовать.
- Заменено: прежние формулировки вида «StratForge-ключи не используются»
  (`docs/EXECUTION_STATE.md`, исторические записи) — неверны, не применять.
- Сам факт общей машины не требует повторного разрешения; выпуск по-прежнему
  только по отдельной команде владельца на конкретный пакет.

Сайт не пересоздавать с нуля. Существующую кодовую базу и историю Git
продолжать.

## Имена: бренд и техкод

- Публичный бренд и домен: **AIpediya**, https://aipediya.com/.
- Внутренний техкод без `y`: пакет Python `aipedia`, пути
  `/srv/aipedia`, Local `data/local/aipedia.sqlite3`, переменные
  `AIPEDIA_*`, cookie/localStorage с префиксом `aipedia`, unix-user и
  Supervisor `aipedia`, ярлыки «AIpedia — Local». Это не опечатка и не
  устаревший бренд — так задумано.
- Не переименовывать техкод в `aipediya` «для единообразия» без отдельного
  поручения владельца. Решение: `D-2026-09-23-brand-vs-tech-name` в
  `docs/DECISIONS.md`.

## Local

- Этот репозиторий. Публичный сайт: https://aipediya.com/
- GitHub: https://github.com/OMNOM-111/aipediya — хранит код, сам по себе
  ничего не выкладывает.
- Local слушает только loopback (`127.0.0.1`), база
  `data/local/aipedia.sqlite3`. Запуск: ярлык «AIpedia — Local», `start.ps1`
  или `tools/local/start-local.ps1`. Остановка только Local:
  «AIpedia — Stop Local» / `tools/local/stop-local.ps1`.
- Кнопка Production открывает https://aipediya.com/ в новой вкладке и
  **ничего не публикует**.
- Снимок каталога в Local заполняется один раз и при повторном запуске
  не перезаписывается. Чужие процессы и занятые порты не останавливать.

## Проверка

Пока изменение не проверено в Local, его нельзя считать готовым — в том
числе к commit.

- Тесты: `.\.venv\Scripts\python.exe manage.py test catalog --settings=aipedia.test_settings`
- Интерфейс: проверить в браузере Local (затронутые маршруты, RU/EN, темы,
  если менялась вёрстка).
- Не считать доказательством публикации ни GitHub, ни кнопку Production.

## Git

Commit и push сохраняют код в историю и на GitHub. Они **не** деплоят
https://aipediya.com/. Не коммитить секреты, `.env`, `data/local/`, SQLite,
`.venv`, логи и backups.

## Production

Без отдельной фразы владельца вида «опубликовать этот commit/tag по
`docs/RELEASE.md`» **не** трогать `/srv/aipedia`, серверную SQLite,
Supervisor, туннель, секреты и публичный HTML.

Если такое разрешение на названный выпуск получено — только
`docs/RELEASE.md`: `tools/build_code_release.py` и
`tools/deploy_code_release.py`. Не подставлять
`tools/deploy_release.py` и `tools/deploy_chronology.py` в обычный
code-only выпуск. Архив не должен содержать Local SQLite.

Процесс выпуска (подтверждено владельцем 2026-09-25, `D-2026-09-25-release-process`):
Develop on Local → QA Local → владелец утверждает выпуск → Production
приводится к утверждённому Local-состоянию → commit, tag и changelog.
Утверждение распространяется на всё проверенное Local-состояние (что
публично, скрыто, отсортировано, переведено, как отображается): отдельные
внутренние изменения внутри него повторно не согласуются. Состояние
публикации переносится манифестом `data/release_state.json`
(`sync_publication_state`), а не копией Local SQLite.

Текущий опубликованный commit указан в `docs/RELEASE.md`; более новый
код этой ветки публикуется только по новой команде владельца.

## Данные и история

- Production: `/srv/aipedia/data/aipedia.sqlite3`
- Local: `data/local/aipedia.sqlite3`
- Неизвестное оставлять пустым, не нулевым. Значимые сведения — со
  источником и датой.
- Не переписывать историю SQL `UPDATE`, `QuerySet.update` или `bulk_update`.
- Модель снимать с публикации, а не удалять вместе с журналом.

## Каноническая база каталога (master)

`AI_CONTEXT/AIpediya_Model_Verification_Master.xlsx` — **единая каноническая
база** AIpediya и главный рабочий реестр. Листы `Models` и `Tools` содержат
**все** записи: опубликованные, скрытые кандидаты и новые находки. Связанные
листы (Offers, Evaluations, Access, Facts, Origins, Tool Platforms) — цены,
оценки, доступ, факты, страны и платформы по Record ID. Решение:
`D-2026-09-24-catalog-master` в `docs/DECISIONS.md`.

- Порядок: запись сначала появляется и проверяется в master; только после
 `PUBLISHED` она синхронизируется в Local, а в Production — лишь по
 `docs/RELEASE.md` и отдельной команде владельца.
- Три разных поля: `Publication Decision` — редакционное решение
 (`PUBLIC` / `ARCHIVE` / `NEEDS_REVIEW`, с `Decision Code`, `Reason`,
 `Decision Date`, `Decision Sources`); `Status` — разрешено ли показывать
 в пакете публикации (`PUBLISHED` / `NEEDS_REVIEW`); `On Local` /
 `On Production` — наблюдённое состояние на дату из Meta. PUBLIC в
 исследовательском запасе — предложение, не команда публиковать.
- ARCHIVE — только конкретное исключение (доказанный дубль/alias/формат/режим,
 технический checkpoint, семейный агрегат, не тот лист, вне охвата) с
 комментарием и источником; для дубля — `Canonical / Parent Record ID` и
 `Relation Type`. Закрытие продукта, нехватка даты или времени — не ARCHIVE.
- Пакет публикации (решение владельца 2026-09-26): ядро (что опубликовано
 сейчас) + явно отобранные проверенные дополнения. Остальной запас —
 отложенный (`[DEFERRED 2026-09-26]` в Notes), сплошная допроверка не нужна.
- Aliases — в колонке `Aliases` через ` | `; пустая ячейка ничего не стирает,
 `<CLEAR>` явно очищает значение при синхронизации.
- `Record ID` (slug) — стабильная идентичность, **никогда** не меняется.
- `Public Number` вычисляется, вручную не правится: хронологический номер
 по verified release date среди `PUBLISHED` (точная дата, иначе `≈` дата;
 при равной дате — имя, затем Record ID). Новая модель получает следующий
 номер; найденная позже историческая встаёт на своё место, последующие
 номера пересчитываются — каждое изменение пишется в лист `Changelog`.
 Непубличные и недатированные записи номера не имеют. Local получает номера
 через `sync-local` (правило владельца 2026-09-26); Record ID и URL постоянны.
- Exact date — только подтверждённая; иначе надёжная дата первого
 публичного существования как `≈YYYY-MM` / `≈YYYY-MM-DD`. Неизвестное —
 пусто.
- Служебные поля: Missing Data (вычисляется), Official Source, Secondary
 Source, Last Verified, On Local, On Production, Notes. Ссылки импорта в
 `Import Sources (unverified)` ничего не подтверждают.
- Импорт/обновление из Local (данные master не перетираются, добавляются
 только новые записи; `--production` лишь читает публичный sitemap):
 `.\.venv\Scripts\python.exe manage.py catalog_master import [--production]`.
 Проверка правил, полноты и расхождений с Local:
 `… manage.py catalog_master check` — перед любой синхронизацией должно
 быть `check: OK`.
- Пересчёт производных полей и черновиков: `… catalog_master refresh`.
 Минимальная синхронизация master → Local: `… catalog_master sync-local`
 (без `--apply` — только план; сначала на копии через `AIPEDIA_DB`;
 рабочий Local — только после приёмки diff владельцем). Не менять каталог
 Local в обход master. Нужен `openpyxl` из `requirements-dev.txt` (только
 Local). Порядок пополнения и инструкция владельцу — `docs/CATALOG_MASTER.md`.
- XLSX не сборка: `tools/pack_ai_context.py` его не перезаписывает.
 Закрыть файл в Excel перед `import`.

## Состояние и пакет для нового чата

Правила в этом файле не заменяют ответ на вопрос «что сейчас сделано
на компьютере». Живой статус — `docs/EXECUTION_STATE.md`. Решения —
`docs/DECISIONS.md` (статусы: предложено / подтверждено владельцем /
отклонено / заменено). Отчёты выпусков — `docs/history/`.
`AI_CONTEXT.md` — сборка, её нельзя вести как вторую копию документов.

**В начале задачи:** прочитать этот файл и `docs/EXECUTION_STATE.md`,
сверить с `git status` и файлами, записать расхождения в статус
(не затирать молча противоречия).

Историю разработки сайта вести по единому порядку `docs/PRODUCT_HISTORY.md`:
перед работой прочитать открытый пакет `docs/timeline.json` и незакрытые
замечания; после значимого этапа обновить реестр и фактический статус. Ярлык
открытия Local-истории находится в `AI_CONTEXT/AIpedia — История сайта.lnk`.

**После законченного этапа** (не после каждого нажатия клавиши):
обновить таблицу Local / GitHub / Production, список файлов, проверки
и конкретный следующий шаг. Идею из обсуждения не записывать как
подтверждённое требование.

**Перед завершением или остановкой:** статус должен содержать
«изменено …; не завершено …; следующим выполнить …». Затем собрать
пакет: `.\.venv\Scripts\python.exe tools/pack_ai_context.py`.
В новый чат прикрепляют `AI_CONTEXT/AI_CONTEXT.md`; при разборе
ошибки или вёрстки — ещё `AI_CONTEXT/AI_CONTEXT.zip`.

Скрипт пишет факты: время сборки, ветку, commit, незакоммиченные файлы,
доступные отчёты. Задачу, решения и причины ошибок пишет исполнитель.
Если статус не упоминает грязные файлы, сборка добавляет предупреждение.
Секреты, `.env` и SQLite в пакет не входят. Сборка не публикует сайт.

## Вне области

Без отдельного поручения не делать: публикацию или откат Production
«заодно» с задачей; правки StratForge; отключение OneDrive; перенос
папки рабочего стола; смену туннеля и секретов.
